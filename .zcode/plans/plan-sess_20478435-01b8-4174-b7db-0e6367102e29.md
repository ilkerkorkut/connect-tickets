# Implement domain logging across API and worker

## Goal
Make both processes observable through structured logs correlated by `request_id` (and, on the worker side, `event_id` / `batch_job_id` / `batch_id` / `repo_id` / `worker_id` / `attempt` / `topic` / `partition` / `offset` / `publisher_id` / `consumer_group`). Use **context propagation** for logger access everywhere (consistent with the worker's existing pattern) and **full observability** across layers.

## Design principles (from AGENTS.md)
- Use `log/slog` only. No new logging libraries.
- **Never log tokens, credentials, raw DB errors, or unrestricted upstream bodies.** Log safe error codes/classifications, never the `Cause` of a `client.RequestError`, and never the raw `fmt.Errorf("...: %w", dbErr)` strings that may contain DSNs/tokens.
- Logs must carry required correlation fields — the existing `ScopedLogger` already does this; reuse it.
- No code comments (project rule). Keep interfaces narrow.

## Layer 0 — logging package (`pkg/logging`)

**`context.go`** — complete the correlation plumbing that's half-built:
- Add `WithPublisherID` / `PublisherIDFrom` and `WithConsumerGroup` / `ConsumerGroupFrom` (keys `publisher_id`, `consumer_group` already exist; only helpers are missing).
- Add `publisher_id` and `consumer_group` to `ScopedLogger(...)` aggregation so they appear in worker logs.
- Add a small `Event(ctx, msg, args...)` helper: reads the logger from context via `LoggerFrom`; if present, emits `ScopedLogger(ctx, logger).Info(msg, args...)`. If no logger in context, it's a no-op (safe for unit tests that don't wire a logger). This is the single entry point handlers/services/gateway use, so call sites stay one-liners and correlation fields are automatic.

No changes to `logger.go` (level/format handling is already complete).

## Layer 1 — API middleware & route lifecycle

**`internal/middleware/access_log.go`** — inject the logger into request context at entry (before `c.Next()`), so every handler/service downstream can reach it via `logging.LoggerFrom`. Keep the existing end-of-request summary log; just move the `WithLogger` injection to the top.

**`internal/middleware/recovery.go`** — capture the recovered value and log it at `Error` with `request_id` (via the context logger), including the goroutine stack, then render the safe response as today. This closes the "panic vanishes" gap. (No token/body leakage — only the stack and the panic value type.)

**`internal/route/lifecycle.go`** (`Serve`/`ServeListener`) — accept a logger or read it from context; log: server listening (`addr`), shutdown initiated, shutdown completed/forced. These are process-lifecycle signals operators need. (Lifecycle is `route`-package; the logger comes from `res.Logger` via the bootstrap seam — pass it into `Serve`.)

**`internal/route/router.go`** — `NewRouter` already receives the logger and wires `AccessLog(logger)`. No signature change.

## Layer 2 — API handlers & services (domain events + classified errors)

The handler layer is where server-side error visibility is restored. Today `WriteServiceError(c, err)` maps an error to a safe HTTP code but drops the cause server-side. Fix: log the classified cause before writing the safe response, and emit domain `Info` events on success.

**`internal/handler/errors.go`** — in `WriteServiceError`, before mapping to a safe response, emit one structured log line carrying: `error_code` (the safe code about to be returned), `http_status`, and a **safe `error_kind`** derived via `errors.Is`/`errors.As` classification (e.g. `duplicate`, `not_found`, `invalid_input`, `invalid_cursor`, `github_rate_limited`, `github_unauthorized`, `github_timeout`, `github_unavailable`, `context_deadline`, `context_canceled`, `internal`). For `client.RequestError`, log `status` and `rate_limit.retry_after`/`reset_at` but **never** `Diagnostic` or `Cause`. For the catch-all `internal_error` branch, log the error type via `fmt.Sprintf("%T", err)` (type only, never the message which may contain a raw DB error/DSN). This is the single point that makes API failures diagnosable without leaking secrets.

**`internal/handler/repos.go`, `batches.go`, `changes.go`, `stats.go`** — emit concise domain `Info` events via `logging.Event(ctx, ...)` on the success paths:
- `repository created` (repo_id, full_name), `repository refreshed` (repo_id, stars, fetched_at), `repository notes updated` (repo_id), `repository deleted` (repo_id), `repository fetched` (repo_id), `repositories listed` (count, has_more), `statistics computed` (total).
- `refresh all scheduled` (batch_id, job_count is not known at handler level — log batch_id only; the service logs the job count).
- `changes listed` (count, has_more), `batch status fetched` (batch_id).
Keep these short (1–3 fields). Failed paths already covered by the `errors.go` change.

## Layer 3 — API services (correlated context for GitHub/DB paths)

**`internal/service/repository/service.go`** — `Create`, `Refresh`, `Delete`, `UpdateNotes` already run inside the request context that carries `request_id`. No logger field needed (read via context). Add `Debug` events for the expensive/important transitions so `LOG_LEVEL=debug` surfaces them: GitHub fetch start/result-classification, duplicate-create detection, refresh txn outcome. Keep `Info`-level events at the handler (above) to avoid double-logging; service-level is `Debug`.

**`internal/service/batch/service.go`** — in `CreateRefreshAll`, log `batch created` with `batch_id`, `job_count` (len of repos) at `Info` (this is where job_count is actually known), correlated to `request_id`. This pairs with the handler's `refresh all scheduled`.

## Layer 4 — Worker: consumer-group lifecycle (currently dropped)

**`internal/event/kafka/consumer.go`** — this is the biggest current gap: the consumer group's `Errors()` channel is buffered-and-discarded and rebalance observation is `nil`. Two fixes:
1. Add a `session` observer implementation (or extend `groupHandler`) that logs `kafka session claimed` (`claims` = topic→partitions map) on `Setup` and `kafka session released` on `Cleanup`, with `consumer_group` from config. Use `sarama.ConsumerGroupSession.Claims()` — already available.
2. Expose the group's error channel through `Consume` (already exists via `Errors()`); the bootstrap seam consumes it and logs each at `Warn` with `consumer_group`.

**`internal/event/kafka/consumer.go` `Consume`** — log `kafka consume started` (`group`, `topic`) once at entry and `kafka consume stopped` on return, including the terminal error if any. These are the "is my worker actually consuming?" signals.

## Layer 5 — Worker: refresh processor (extend existing logging)

**`internal/service/worker/consumer.go`** — already logs `refresh record processed` once per record. Extend so the important sub-decisions are visible too:
- Keep the existing single summary line (it's the right shape).
- Add `Debug` lines for: claim outcome (`claim_state`), cooldown deferral (no attempt consumed), repository load failure classification, retry scheduled (`retry_at`, `attempt`, `error_code`), terminal failure (`attempt`, `error_code`), invalid payload recorded. All correlated to `event_id`/`batch_job_id`/`repo_id` already in context.
- `messageContext` already populates correlation keys; also add `consumer_group` there (from a new field on `Consumer` set at construction, sourced from `config.Kafka.ConsumerGroup`).

## Layer 6 — Outbox publisher (currently logs nothing)

**`internal/producer/outbox/publisher.go`** — this component is completely silent today. Add:
- `Run`: `outbox publisher started` (`publisher_id`, `poll_interval`, `batch_size`, `lease`) at entry; `outbox publisher stopped` on return.
- `RunOnce`: `outbox poll cycle` at `Debug` with `claimed` count.
- `publish`: `outbox event published` (`event_id`, `event_type`, `partition_key`, `aggregate_id`, `attempt`) at `Info` on success; `outbox publish failed` (`event_id`, `safe_error` ∈ {`invalid_outbox_payload`, `kafka_publish_failed`}) at `Warn` on release.
- Inject `publisher_id` into context at `Run` start (via `logging.WithPublisherID`), so every publisher line is correlated. Read the logger from context (the seam already calls `publisher.Run(logging.WithLogger(ctx, res.Logger))`).

## Layer 7 — GitHub gateway (exactly-one-call observability)

**`internal/cache/github/cache.go`** — the cache-miss lock / cooldown / exactly-one-call behavior is a core requirement and currently invisible. Add `Debug` events (via context logger) for: cache hit, cache miss, lock acquired, lock wait (polling), upstream fetch result-class (never the body), cache store write. Also `Warn` on cooldown activation and `Debug` on cooldown check. These are guarded by `LOG_LEVEL=debug`, so they don't clutter default production logs but are available when diagnosing rate-limit/lock issues.
- Cooldown recording (`ratelimit.go` `RecordCooldown`): log `github cooldown recorded` (`until`) at `Warn` when a cooldown is actually set.

## Layer 8 — Bootstrap seams (wiring + lifecycle)

**`internal/bootstrap/seams.go`**:
- `runAPIFn`: pass `res.Logger` to `route.Serve(...)`; populate `consumer_group`/`worker_id` context where appropriate.
- `runWorkerFn`: read `consumer.Errors()` in a goroutine and log each at `Warn` (with `consumer_group` from config); wire the session observer into `consumer.Consume(ctx, processor, observer)` instead of `nil`; inject `consumer_group` into the context passed to `Consume`.
- `runPublisherFn`: inject `publisher_id` context (publisher already self-generates an owner UUID; reuse it).
- Log `worker started` / `publisher started` / `worker stopped` / `publisher stopped` at the seam boundaries (component-level lifecycle), with the owner/worker IDs.

**`internal/bootstrap/run.go`** / **`lifecycle.go`**: log `configuration loaded`, `bootstrap failed` (cause type only — config/DB/Redis errors may contain secrets), and `shutdown complete`. Already partially done (`bootstrap complete`, `starting`); extend minimally.

**`cmd/api/main.go`**, **`cmd/worker/main.go`**: unchanged (errors go to stderr as today).

## Layer 9 — Config

**`config/config.go`** — no schema change. `Log.Level`/`Log.Format` already exist and drive `NewLogger`. Document the new `debug` utility in `.env.example` only if needed (likely just a comment that `LOG_LEVEL=debug` enables gateway/cache-detail logs). No behavior change.

## Tests

Per AGENTS.md ("every behavioral change requires tests"), add focused deterministic tests:
1. **`pkg/logging/context_test.go`** — `WithPublisherID`/`PublisherIDFrom`/`WithConsumerGroup`/`ConsumerGroupFrom` round-trip; `ScopedLogger` includes publisher_id & consumer_group; `Event` is a no-op when no logger in context and emits scoped fields when present (capture via `slog.NewTextHandler` into a `bytes.Buffer`).
2. **`internal/middleware/recovery_test.go`** — panic is logged (capture buffer) with stack, then safe response rendered; request_id preserved.
3. **`internal/handler/errors_test.go`** (or extend `router_test.go`) — `WriteServiceError` logs the safe `error_code`+`error_kind` for (a) a `client.RequestError` (rate-limited) — assert `retry_after` present and **no** diagnostic leaked, (b) a raw `errors.New("postgres://token@host ...")` internal error — assert the raw message does **not** appear in the log buffer, only `error_kind=internal` and the type name.
4. **`internal/service/batch/`** — extend to assert `batch created` is logged with `batch_id`+`job_count` (integration test already spins up DB; add a log-capture assertion or a unit test with a fake logger via context).
5. **`internal/producer/outbox/publisher_test.go`** — inject a logger via `logging.WithLogger(ctx, logger)` into `RunOnce`/`publish`; assert `outbox event published` on success and `outbox publish failed` with `safe_error=kafka_publish_failed` on producer failure. (Existing fakes already support this; just add context-logger injection.)
6. **`internal/event/kafka/`** — add a `groupHandler` observer unit test asserting `Setup`/`Cleanup` log claimed/released claims (using a fake `sarama.ConsumerGroupSession` or by extracting the observer into a testable shape).
7. **`internal/service/worker/consumer_test.go`** — extend to assert `Debug` retry/failure lines carry `error_code` (capture buffer), on top of the existing summary line.

Use deterministic synchronization (buffer-based log capture) — no `time.Sleep`. Concurrency-sensitive tests run under `-race`.

## Verification (Definition of Done)
1. `gofmt -l .` clean.
2. `go test ./...` green; `go test -race ./internal/producer/... ./internal/service/worker/... ./internal/event/...` green.
3. `go vet ./...` clean.
4. `make ci` (or the equivalent lint+build+test) passes.
5. Spot-check: run `make run-all` (or `docker-up`) and confirm logs now contain, for a create→refresh→refresh-all cycle: `repository created`, `repository refreshed`, `batch created` (with job_count), `outbox event published`, `refresh record processed`, plus `consumer_group`/`publisher_id`/`request_id` correlation throughout. Confirm no token/DSN/raw-diagnostic appears in any log line.
