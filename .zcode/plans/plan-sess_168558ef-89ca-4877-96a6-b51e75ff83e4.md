## Goal

Create `scripts/smoke-concurrency-live.sh` — a bash script that simulates our concurrency test against an already-running API, worker, and infra (Postgres, Redis, Kafka), then prints the resulting database state for inspection.

## What the script does (mirrors `TestConcurrentRepositoryCreation` + the smoke flows in `scripts/smoke-test.sh`)

1. **Preflight**: require `curl`, `jq`, `docker` (for DB inspection); wait for `GET /healthz` to succeed (default `API_URL=http://localhost:18080`, configurable via env).
2. **Pick a test identity**: default `GITHUB_OWNER=octocat` / `GITHUB_NAME=hello-world` (env-overridable). Compute `normalized_full_name=lowercase(owner/name)`.
3. **Reset the test identity** (so re-runs are faithful to the concurrency scenario):
   - `DELETE /api/repos/:id` any existing tracked row for that identity (loop over `GET /api/repos` to find it; soft-delete is fine — the API does tombstoning).
   - Flush the Redis cache + lock keys for the identity: `docker compose --project-name github-tracker exec -T redis redis-cli DEL github:repo:v1:<normalized> github:repo-lock:v1:<normalized>`.
   - If the row exists but is already tombstoned (deleted_at set), the unique index is partial (`WHERE deleted_at IS NULL`) so a fresh create will succeed regardless.
4. **Concurrent burst** (the core concurrency test): spawn `CONCURRENCY` (default 5) background `curl POST /api/repos` with the same `{owner,name}`, gated by a shared `start` signal (a temp file / `xargs` barrier) so they truly race. Record each response's HTTP status + body to a temp file.
5. **Assert the concurrency invariants** (same as the test): exactly **1× 201**, **(N−1)× 409** with `error.code == repo_already_tracked`, and **0 unexpected**. Print a one-line tally. Capture the created `repo_id` from the 201.
6. **Notes update** → `PATCH /api/repos/:id` (expect 200), persists notes → produces a `notes_updated` change row.
7. **Synchronous refresh** → `POST /api/repos/:id/refresh` (expect 200), hits GitHub, produces a `refreshed` change row.
8. **Batch refresh-all** → `POST /api/repos/refresh-all` (expect 202, returns `batch_id`); poll `GET /api/batches/:batch_id` until `complete == true` (timeout `POLL_TIMEOUT_SECONDS`, default 60). Drives the worker → produces `batch_jobs`, `job_attempts`, and `outbox_events` (published refresh messages).
9. **Print a DB summary** via `docker compose --project-name github-tracker exec -T postgres psql -U tracker -d tracker -c '<query>'`, scoped to the test identity so unrelated rows are excluded. Sections:
   - `repositories` row for the identity (id, owner, name, stars, notes, fetched_at, deleted_at).
   - `repository_changes` rows ordered by `sequence` (sequence, operation, changed_at) — expect `created`, `notes_updated`, `refreshed` (commit-ordered).
   - `batches` + `batch_jobs` for the batch (status, attempt_count, last_error_code).
   - `job_attempts` for those batch jobs (attempt_number, worker_id, result, error_code, duration_ms).
   - `outbox_events` for the repo's refresh message (event_type, status, publish_attempts, published_at).
   - Counts row at the end (total repos tracked, total changes for identity).

## Configuration (env-overridable, matching existing scripts)
- `API_URL` (default `http://localhost:18080`)
- `GITHUB_OWNER` / `GITHUB_NAME` (default `octocat` / `hello-world`)
- `CONCURRENCY` (default `5`)
- `POLL_TIMEOUT_SECONDS` (default `60`)
- `COMPOSE_PROJECT` (default `github-tracker`) — for the `docker compose exec` DB/Redis calls.
- Postgres/Redis container names follow the compose service names (`postgres`, `redis`), DB `tracker`, user `tracker`.

## Conventions matched
- `#!/usr/bin/env bash` + `set -euo pipefail`, `mktemp -d` work dir, `trap cleanup EXIT`, `fail()`/`require_command` helpers — same shape as `scripts/smoke-test.sh`.
- `request()` helper modeled on `scripts/smoke-test.sh` (status + body capture, fail-on-mismatch).
- No code comments (per AGENTS.md), `chmod +x` the file.
- Add a `smoke-concurrency-live` target to the `Makefile` `.PHONY` list and a target body (`@scripts/smoke-concurrency-live.sh`), next to the existing `smoke-concurrency` target.

## Not included (intentional)
- No `TestConcurrentWorkerRateLimitSchedulesRetries` simulation — that scenario needs a mock GitHub returning `429`/`Retry-After`, which is impossible against real GitHub infra.
- The script only **resets** the one test identity; it never wipes unrelated data.
- DB write/cleanup is limited to the single test identity and its two Redis keys.
